The Scenario

When ASCTE's new Sentinel Center opens, there will be a school store selling spirit wear, school supplies, and water bottles. The school needs to design a wireless tap-to-pay payment system so students can make purchases quickly and safely using their phones or payment cards.

Think about using Apple Pay, Google Pay, or tapping your card at a store - you tap your device on a reader and the payment goes through wirelessly. That's what this system will be like!

Your job: Analyze this payment system through the engineering lifecycle and identify what types of cyber protections are needed at each phase.

Remember the CIA Triad:

  • Confidentiality: Keeping information private and secret from people who shouldn't see it
  • Integrity: Making sure information is accurate and hasn't been changed by unauthorized people
  • Availability: Making sure the system works when people need it

Remember Data States:

  • Data at Rest: Data that is stored somewhere (in a database, on a hard drive, etc.)
  • Data in Transit: Data that is being sent from one place to another (over wifi, through cables, etc.)
  • Data in Use: Data that is currently being processed or displayed on a screen

Part 2: Design Process Security Analysis

Now you'll think about security during the Design Process phases of the engineering lifecycle.

Phase 1: Define Problem

This is where we clearly state what we're trying to accomplish.

Identify one cybersecurity concern related to the CIA triad that could affect this payment system. State which part of the CIA triad it relates to.

Example: Payment card information could be seen by unauthorized people during transmission (Confidentiality concern)

Phase 2: Generate Concepts

This is the brainstorming phase where we think of different ways to address security needs.

When payment information travels wirelessly from a phone or card to the payment reader, what state is the data in? Why does this create a security concern?

Remember: Data at rest, data in transit, or data in use?

Payment card numbers need to be kept confidential. During which data state(s) does the payment card number need confidentiality protection? Check all that apply and explain why.

Think about: When the card number is stored, when it's being sent, when it's displayed on screen

Phase 3: Finalize Design

Now we make specific decisions about how the system will work.

The system will keep records of all transactions (what was bought, when, and how much). Which part of the CIA triad is MOST important for these transaction records? Explain why.

If the wireless payment system stops working during lunch, the store might use a paper backup system to write down purchases. What information would need to be written down? Which part of the CIA triad would be MOST at risk with a paper backup system compared to the digital system?

Phase 4: Create Prototype

This is when we build a working model of the system to test.

Even in a prototype, we need to think about security. Name one part of the CIA triad that should be tested in the prototype and explain why it's important to test it early.

Phase 5: Test Prototype

Testing helps us find problems before the system goes live.

During testing, you notice that when a payment goes through, the full card number briefly appears on the payment terminal screen. Which part of the CIA triad is at risk? What data state is the card number in when it's displayed on the screen?

How could you test whether the system remains available when many students try to use it at the same time (like during lunch rush)?

Phase 6: Verify Solution

Before presenting the solution, we verify that it meets security requirements.

Look back at all the phases you've worked through (Define Problem, Generate Concepts, Finalize Design, Create Prototype, Test Prototype, Verify Solution, Present Solution). You've been thinking about cybersecurity at EACH of these phases, not just at the end.

Why is it important to think about cybersecurity throughout the entire design process instead of just adding security features at the end?

Think about: What could go wrong if you only think about security after everything is already built?

Phase 7: Present Solution

When presenting the final system design, security features need to be explained.

Write 2-3 sentences explaining to the principal why this payment system protects student information. Use at least two parts of the CIA triad in your explanation.
